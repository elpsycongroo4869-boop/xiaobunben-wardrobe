# 宿主接线与复用边界

## 启动到开箱

1. 读取一次当前入口和创作工作流。确认角色配置。只有创作者实际需要时才查世界卡或摄影专项参考。
2. 在同一份底稿里完成完整世界、摄影取景、透视与动作支点复核、最终情绪复核、六段拍前说明和创作状态。镜头的可见动作及衣装由程序绑定到摄影记录。权威情绪及表情由程序映射，不需要创作者再手写一遍。
3. 一次调用 `scripts/story_start.py prepare`。使用独立目录，并保存这次生成的 ZIP 和单独的 manifest SHA-256。若持久化需要上传，上传这一个 ZIP。准备过程已经独立读回压缩包并核对内容，后续跨会话取签时再做只读复核。
4. 支持 `GenUI.issueNewTurn` 的宿主可选 `--route new_chat`。读出实际验证过的 `button_manifest.json`，把 `button_label` 渲染为真按钮，点击处理器只调用 `GenUI.issueNewTurn(full_user_message)`。使用同一签内的 `creative-notes-button.html` 和 `creative-status.html`，状态不剧透，创作说明默认收起。确认画面上实际有启用的点击控件后再记录为按钮出现。
5. 本地浏览器使用默认的 `copy_only`。生成的 `open.html` 启用前核对消息 SHA-256。实际点击后原样复制，或者提供同一文本的手动复制。用户粘贴并发送后才交给图片宿主。普通 Chat 文字适配的明确确认与这里的点击是两个不同的入口。

将 ZIP、可查看底稿与打开按钮的权限限定在对应创作者及其获准的使用者。开箱卡以视觉隐藏维护惊喜，用户若查看本地文件内容可以读到全文。SHA-256 核对源和交付载荷一致性，独立 pin 可辨认此前保存的 manifest。它没有签名密钥。

## 文件与版本

`role-profile.json` 保存角色来源和实际设定。`creative-brief.json` 保存原始世界和可见场景。`photographer-selection.json` 保存画内外选择并和 `draw.json` 绑定。`english-details.json` 继承 21 个源维度，旧字段 `feminine_presence` 的对应字段为 `visible_expression`。`button_manifest.json` 含路由、逐字提示词和说明、状态指纹。`manifest.json` 记录包内各文件 SHA-256。任何对正文、角色或镜头的改动都需要新签。

新版的 30% 压缩分母采用 21 项源、完整世界和构图理由的展开文本。当前范围仍是 1100–2500 字符。历史封签验签保留原有的压缩分母、版本和格式。

当前底稿的 `camera_plan.subject_distance_m` 为相机到画内主体的估计距离，单位为米，须为有限正数。编译把距离与机位写入 Camera，把景别与画内构图写入 Frame。想用旧底稿做一份新签时，先按当前模板补写距离并复核取景。已封存的 rc.1 至 rc.3 封签按原编译规则只读校验。底稿核对的是拍摄方案，实际比例由出图后对照当次成片复核要点判断。

当前版将 `choice.costume_plan.visible_style_detail` 放在出图 Outfit 的开头。`scene_design.wardrobe` 填其余可见衣装。程序把两者合并，在完整封签的 `scene-design.json` 记录交付版衣装。衣装可见而改造在画外时，在 `offscreen_not_requested` 指出具体被裁掉的改造。用旧底稿制作新签时按当前模板补写或声明画外项，已封存的 RC.1 至 RC.5 按其原格式验签。角色审美由角色卡和创作者决定，实际效果用成片对照。
